## 0. 结论摘要

业务闭环完整，工程形态仍是「一组单机脚本 + 一个 3.6k 行的 Tkinter 外壳」。
上一轮 P0 清单里 **P0-1（版本单一源）、P0-3（SQLite 加固）、P0-4（批量提交）、P0-5（数据集原子替换）已落地并可在代码中逐一验证**；
**P0-2（启动阻塞）、P0-6（发布整树复制）、P0-7（仓库卫生）仍未闭环**。

本轮新确认 **3 个 P0 级缺陷**（其中两条直接造成数据/结果错误），另有 2 条上轮已指出但未闭环的 P0
（启动阻塞、发布白名单漏包）。最需要优先处理的是四条：

1. **删除「外部导入模型」会删掉用户自己的原始目录**——导入是原路径登记（不复制），删除是 `shutil.rmtree`：
   `bird_crawler_gui.py:2687` + `model_library.py:872/943`；
2. **点「停止训练」后无法续训**——Windows 的 `terminate()` 是 `TerminateProcess`，训练脚本的
   `except KeyboardInterrupt` 与 `finally` 都不会执行，断点提示文件不落盘，GUI 的续训勾选框因此永久置灰；
3. **部位框系统性错位一格**——检测器输出标签是 1 基（背景=0），而 `PART_TO_DETECTOR_IDX` 是 0 基，
   比较处直接用裸标签：选 `back` 永远不命中，选 `beak` 拿到的是 `back` 的框；
4. **照片浏览第一次必然全盘扫描**——库里的 `local_path` 是相对「类群目录」的，而 GUI 按 `data/` 根拼接，
   必然落空，于是退化为对整个 `data/` 的 `rglob` 建索引，且该索引永不失效。

另有：视觉分析页首次切换可能在 Tk 主线程里「扫描所有盘符找 torch 解释器」（每候选 20s 超时）；
以及一处发布级缺口——`程序_混合加密` 实际产物**不含 `part_model_training/`（11 个文件）与 `LICENSE`**，
即发布版里「部位分割 / 部位检测」训练一按就报「文件不存在」。

## 1. 业务逻辑

### 1.1 四条主线

| 主线 | 入口 | 产物 | 状态落地 |
|---|---|---|---|
| 采集 | `main.py batch/download`、GUI 下载页、拖入页 | `data/taxon_<id>_<名>/photos/` | `raw_data.db` + `bird_observations.db` |
| 治理 | `health` / `cleanup` / `migrate` / `panel` | 健康报告、修复动作、浏览器面板 | 同上 + 整库备份 |

| 推理 | 视觉分析页 → `qa_server.py` 子进程 | 标注图 + 中文结论 | 模型库注册表 + 内存缓存 |

### 1.2 一次数据流的完整路径（以「拖入图片 → 训练 → 推理」为例）

```
拖入图片 ──drop_crawl_interface._import_images_for_kind──► 文件夹名解析种类
   │  SHA-256 内容去重 → upsert_local_photo（photo_id 负数本地编号）
   ▼
data/taxon_<id>_<名>/photos/  +  bird_observations.db(photos.local_path = "photos/obs_x.jpg")
   │  注意：local_path 相对「类群目录」，不是相对 data/
   ▼
GUI「训练数据集」勾选类群 ──dataset_exporter.py──► 观察级 8:1:1 硬链接导出
   │  （同一观察的全部照片只进一个划分——防泄漏正确）
   ▼
GUI「模型训练」──model_trainer.py 子进程──► 模型库 <基名>_<月日>_<NNN>/
   │  registry.json + best_model.pt + labels.json + 评估报告
   ▼
GUI「视觉分析」──QaServiceClient──► python qa_server.py（JSON 行协议，fd 级通道隔离）
```

### 1.3 状态与产物矩阵

| 状态 | 位置 | 写入者 | 一致性弱点 |
|---|---|---|---|
| 观察/照片 | 两个 SQLite 库 | 爬虫、拖入、健康修复 | 已开 WAL + busy_timeout（P0-3 已修）；两库一致性靠 `db_health_check` 事后检查 |
| 模型库 | `model_library/registry.json` | 训练子进程、GUI 导入/删除/激活 | **读—改—写整文件，无跨进程锁**（T1） |
| 训练断点 | `<模型目录>/resume_state.pth` + `model_library/last_interrupted.json` | 训练子进程 | 仅 `KeyboardInterrupt` 分支写后者，**GUI 停止走不到**（B2） |
| 数据集 | `train_datasets/registry.json` + 目录 | GUI（子进程只写 `.名称.building`） | `promote_build` 内 remove + add 两次读改写（B3） |
| 视觉系统位置 | `model_library/settings.json` | GUI 三级探测后回写 | 冻结形态下 `BASE_DIR.parent.parent` 语义漂移 |

### 1.4 四条隐形契约

1. **文件即状态**：模型库、数据集、断点、`training.lock` 全是「约定好的路径」而不是接口。
2. **子进程即 API**：GUI 拼命令行 + 解析子进程 stdout 文本（见 3.3，共 4 套不同格式）。
3. **路径即配置**：全部由 `BASE_DIR = Path(__file__).parent` 推导；视觉系统目录靠三级探测 + `sys.modules` 兜底（`bird_crawler_gui.py:2988-3005`）。
4. **解释器即环境**（本轮新增）：GUI 自身不含 torch，所有训练与推理都必须「找一个外部 python」；
   这个查找过程被写进 UI 线程（`_detect_torch_python:1746-1807`）。

### 1.5 业务逻辑层缺陷

| # | 位置 | 问题 | 影响 |
|---|---|---|---|
| B1 | `dataset_exporter.py:379-399` vs `model_trainer.py:653-694` | **两套划分口径**：导出按「观察」划分（正确），训练页勾「按比例自动划分」时按「图片」划分 | 用户一旦选自动划分，同一观察的多张照片会跨 train/val，防泄漏工程白做 |
| B2 | `bird_crawler_gui.py:2297-2301` + `model_trainer.py:1701-1740` | 停止训练用 `terminate()`；`except KeyboardInterrupt` / `finally` 在 Windows 上都不执行 | 不写断点提示文件 → 续训永久不可用；返回码 1 被当作「异常退出」 |
| B3 | `dataset_registry.py:232-233` | `promote_build` 内先 `remove_dataset` 再 `add_dataset`（两次整表读改写） | 两步之间崩溃 → 数据集目录在、登记没了 |
| B4 | `download_inaturalist.py:558` vs `bird_crawler_gui.py:3199-3217` | `local_path` 语义（相对类群目录）没有文档也没有唯一解析函数，GUI 与导出脚本各自解释 | GUI 全盘扫描；同名文件串图 |
| B5 | `bird_crawler_gui.py:687`（`ds_min_var=0`） | 默认允许 1 张图成类 | 训练集类别极不均衡也照样放行，指标失真 |

### 2.3 缺失的分层

当前是「脚本 + 外壳」，没有可被复用的领域层：

- **无 `core/`**：DB 访问散在 4 个模块（`db.py` 只是连接工厂），HTTP 有两套栈

  注册表读写各写各的（`model_library` / `dataset_registry` 两套几乎相同但互不复用）。
- **无 `repos/`**：SQL 直接写在 GUI 回调里（`_load_dataset_taxa:765`、`_load_observations:3330`…），
  换一个页面就要重写一遍查询。
- **无统一日志**：全仓 `getLogger` 出现 **0 次**，`print(` 出现 **146 次**；
  GUI 只能把 stdout 灌进 `ScrolledText`，出问题后用户没有可提交的日志文件。

## 3. GUI 架构

### 3.1 现状：一个类装下 9 个页

`bird_crawler_gui.py`：**3592 行、1 个类、114 个方法、147 个实例属性、9 个页签、78 处 `messagebox`、9 处 `Popen`、6 个线程、4 个队列泵、26 处 `getattr(self, "…", None)`**。

- 页面之间没有 `Page` 抽象，交叉引用靠 `getattr(self, "train_dataset_combo", None)` 防御式访问
  （`_refresh_dataset_list:976` 直接改训练页的下拉框）。
- 界面状态有**三处真相**：`tk.StringVar/IntVar`（界面）、实例属性（`_drop_progress_photo_mode` 等）、
  磁盘注册表（模型库/数据集）。三者没有单一同步点，只能靠回调互相 `refresh`。
- 页签构建顺序即初始化顺序：`__init__:236` 一次性构建 8 个页，只有「视觉分析」是惰性的（`_build_vision_tab:2942`）。

### 3.2 启动时序（实测）

```
__init__:201
 ├─ _build_banner / _build_status_bar            (~0ms)
 ├─ _build_notebook:236
 │   ├─ _build_dataset_tab:609
 │   │   ├─ _load_dataset_taxa:749   → SQL: photos JOIN observations GROUP BY taxon_id
 │   │   └─ _refresh_dataset_list:750→ 读 registry.json
 │   ├─ _build_train_tab:1044
 │   │   └─ _on_train_mode_changed:1303
 │   │       └─ _fill_recommended_params:1690
 │   │           ├─ _detect_train_hardware:1630 → subprocess.run(timeout=60)  ← 实测 2.86s
 │   │           └─ _count_dataset_images:1657 → rglob 最多 50 万个文件
 │   ├─ _build_models_tab:2332 → refresh_models:2402 → _refresh_base_model_options（再读 2 次注册表）
 │   └─ _build_vision_tab:2942（惰性，好）
 └─ _ensure_databases:237 → _refresh_taxon_filters
```

实测：本机（已装 torch，热缓存）单这一项 **2.86s**；冷盘/杀软扫描的机器即前序文档所述 5–15s。
`_count_dataset_images` 在本机因目录为空而≈0，但「含数据版」安装包里该目录有 5 万张图时，
`rglob` 是秒级到十秒级。

**反向的优先级错误**：最重的训练页同步加载，而「数据浏览 / 照片浏览 / 统计与说明」三个页
启动时根本不加载（`_load_observations`/`_load_photos`/`_load_stats` 只在按钮回调里调用），
用户打开看到的是空表格——**该慢的没慢，该有数据的没数据**。

### 3.3 线程与子进程：4 套并列实现

| 页面 | 启动 | 结束标记（字符串匹配） | 进度解析 | 编码策略 |
|---|---|---|---|---|
| 下载控制 | `_start_download:3257` | `"[下载进程已结束]"` | 无 | `_SUBPROC_OUTPUT_ENCODING`（frozen→gbk） |
| 拖入文件 | `_spawn_drop_proc:491` | `"[拖入处理进程已结束 rc="` | 2 条正则（`:144-145`） | 同上 |
| 训练数据集 | `_start_dataset_export:895` | `"__数据集生成结束__ rc="` | 无 | 同上 |
| 模型训练 | `_run_train_subprocess:2220` | `"[训练进程已结束 rc="` + 正则取 rc | JSON 行 `[METRIC] ` | 固定 utf-8 |

四者都是「`Popen` + 读线程 + `queue.Queue` + `root.after(200)`」，但结束语义、编码、进度格式各不相同。
任何一处文案改动（改一句 `print`）都会让对应页面的按钮永久卡在禁用态——这是纯文本契约的必然代价。

## 4. 训练与模型层

### 4.1 链路

`model_trainer.py`（1888 行，`main()` 单函数约 840 行）：
扫描/划分 → 增强 → 训练循环（每轮写 `best_model.pt` / `last_model.pt` / `resume_state.pth` / `training_history.json`）
→ 结束评估 → `model_library.register_model()` 入库。
部位训练走 `part_model_training/` 的 4 个脚本，由 `_start_part_train:1984` 按「分割/检测 × 预设/通用」四分支拉起。

### 4.2 数据正确性

| # | 位置 | 问题 | 影响 |
|---|---|---|---|
| T1 | `model_trainer.py:653-694` | `per_class_adaptive_split` 按**图片**划分（`671-672` 排序+打乱），不按观察归组 | 选「按比例自动划分」后，同一观察的连拍会跨 train/val（导出器 `dataset_exporter.py:379-403` 是按观察划分的，两套口径并存） |

## 8. 优化清单

> 原则：不引入新依赖、不改 CLI 契约、每项可独立回滚、改完有明确验收。

### P0-1 启动不阻塞（G1 + G7）

`__init__` 只做内存构建，磁盘与子进程全部推迟到首帧之后：

```python
# __init__ 末尾
self.root.after(1, self._deferred_startup)

def _deferred_startup(self) -> None:
    """首帧渲染后再触碰磁盘：启动路径保持纯内存。"""
    self._ensure_databases()
    self._load_dataset_taxa()
    self._refresh_dataset_list()
    self._refresh_taxon_filters()
    self._load_stats()          # 顺手修掉「统计页打开是空白」
    self._probe_hw_async()      # 硬件探测一律异步
```

硬件探测拆成「同步取值 + 异步刷新」：

```python
def _fill_recommended_params(self) -> None:
    ...
    has_gpu, gpu_mem_gb = self._train_hw_cache or (False, 0.0)   # 首屏用保守值
    ...
    if self._train_hw_cache is None:
        self._probe_hw_async()

def _probe_hw_async(self) -> None:
    """后台探测训练硬件，完成后在主线程重算推荐参数（只探测一次）。"""
    if self._hw_probing:
        return
    self._hw_probing = True
    def work() -> None:
        result = self._detect_train_hardware_blocking()   # 原函数主干，去掉 UI 依赖
        self.root.after(0, lambda: self._on_hw_probed(result))
    threading.Thread(target=work, daemon=True).start()
```

`_count_dataset_images` 同理：已登记数据集直接读 `registry.stats.images`，未登记才后台 rglob。

**验收**：空数据目录下从双击到可交互 < 1s；训练页首屏不等待解释器探测；统计页打开即有数据。

## 9. 不建议做的事

1. **换 Qt / Electron**：Tk 够用，缺的是分层；换框架会把问题原样搬过去，还会丢掉现在的单文件零依赖启动优势。
2. **把训练搬进 GUI 进程**：子进程隔离是正确决策（GUI 不含 torch 也是对的），只该换协议。
3. **继续投入源码加密**：自解密文件保护不了 Python；要保护就保护模型权重与 API 密钥。
4. **继续加页签**：9 页已接近认知上限，新能力优先做成现有页的模式切换。
5. **为 4 个脚本各写一套进度协议**：统一到 `qa_server` 那种 JSON 行协议，一次到位。
