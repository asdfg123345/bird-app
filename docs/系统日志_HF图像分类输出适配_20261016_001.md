# 系统日志：HF 图像分类模型前向输出适配（ImageClassifierOutput）

- **事件类别**：HF 图像分类模型前向输出适配（bug 修复）
- **日期时间**：2026-10-16
- **序号**：001
- **涉及项目**：发布_鸟类应用_20261015_002（主要维护版本）

---

## 一、提示词总结

用户用外部导入的 ViT 模型（bird_species_image_detection）作为训练起点继续微调，训练在批大小探测阶段崩溃，报错：

```
TypeError: cross_entropy_loss(): argument 'input' (position 1) must be Tensor, not ImageClassifierOutput
```

要求定位并修复。

## 二、问题定位（根因）

训练脚本 `model_trainer.py` 中有 4 处 `model(imgs)` 前向调用，都把输出直接当作 logits 张量传给损失函数或做 `argmax`/`topk` 计算。

- torchvision/timm 模型（ResNet50、ResNeSt101）的 `forward` 返回纯 logits 张量，原代码正确；
- HuggingFace 图像分类模型（ViTForImageClassification 等）的 `forward` 默认返回 `ImageClassifierOutput` 数据类对象，真正的 logits 位于其 `.logits` 属性。

此前训练起点只用 ResNet50（torchvision），未暴露此问题；改用 HF ViT 后，`criterion(outputs, labels)` 收到的是 `ImageClassifierOutput` 而非 Tensor，触发 TypeError。

## 三、修复内容

在 `model_trainer.py` 新增统一的 logits 提取函数，并把 3 处 `model(imgs)` 调用点改为经该函数提取：

```python
def _extract_logits(outputs):
    """从模型前向输出中提取 logits 张量。

    兼容两类输出：torchvision/timm 的纯 logits 张量；HuggingFace 图像分类
    模型的 ImageClassifierOutput（logits 位于 .logits 属性）。
    """
    if hasattr(outputs, "logits"):
        return outputs.logits
    if isinstance(outputs, (tuple, list)) and outputs:
        return outputs[0]
    return outputs
```

修改的三处调用点：
1. `probe_batch_size`（批大小实测探测的虚拟前向）；
2. 训练循环（每轮前向 + 反向）；
3. 验证/评估循环（`_evaluate` 的前向）。

## 四、验证

1. **语法验证**：`python -m py_compile model_trainer.py` 通过。
2. **端到端训练验证**：用 bird_species_image_detection（vit_hf）作为基础模型，3 类小数据集训练 1 轮：
   - `[探测] 批大小实测通过: batch=64`（此前在此处崩溃，现已通过）；
   - `[Epoch 1/1] 完成：train_loss=1.0529 train_acc=0.5556 ...` 训练循环正常；
   - 无 TypeError / ImageClassifierOutput 报错，验证集/检测集评估正常完成。
