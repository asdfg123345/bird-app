# 系统日志：验证集为空防护修复

- **事件类别**：验证集为空防护修复（bug 修复）
- **日期时间**：2026-10-16
- **序号**：001
- **涉及项目**：发布_鸟类应用_20261015_002、发布_鸟类应用_20261016_001

---

## 一、提示词总结

用户反馈训练界面中验证损失、Top-1、Top-5、宏平均 F1 四项指标均显示为 0，怀疑是计算公式错误。经排查，确认不是公式错误，而是验证集为空导致的。用户要求解决该问题，并同时解决排查中发现的健壮性缺陷。

## 二、问题定位

### 1. 现象

训练损失正常下降（如 3.5095 → 1.9766），但验证损失、Top-1、Top-5、宏平均 F1 均为 0.0000。

### 2. 根因

- 指标计算公式本身正确，字段名在训练脚本（输出 `top1/top5/macro_f1`）与 GUI（读取同名字段）之间完全匹配。
- 真正原因是**验证集样本数为 0**。评估函数用 `max(1, total)` 做除零保护，当验证集为空（total=0）时，`0 / 1 = 0`，四项指标全部算成 0。
- 触发条件：选择「使用目录既有划分」时，数据目录下缺少 `val` 子目录（或为空）。

### 3. 原代码缺陷

训练脚本只检查了训练集为空（`counts["train"] == 0` 报错退出），**未检查验证集为空**，导致静默训练、静默输出全 0 指标，容易让用户误判为公式错误。

## 三、修复内容

在 `model_trainer.py` 数据扫描后的校验处，新增两道防护（两个版本同步修改）：

### 1. 验证集为空 → 明确报错退出

验证集驱动早停与最佳模型选择，为空属致命数据问题，改为报错并给出两条解决路径：

```python
if counts["val"] == 0:
    log("[错误] 验证集为 0 张，无法计算评估指标（损失/Top-1/Top-5/宏F1 会显示为 0）。")
    log("       请二选一解决：")
    log("       1) 在数据目录下补充 val 子目录（结构：val/类别名/图片）；")
    log("       2) 改用自动划分（--auto-split，按比例从训练集切出验证/检测集）。")
    return 1
```

### 2. 检测集为空 → 警告继续

检测集仅用于训练结束时的最终评估，不影响训练主流程，改为警告而非报错：

```python
if counts["test"] == 0:
    log("[警告] 检测集为 0 张，训练结束时的检测集评估指标将显示为 0。")
```

### 3. 修改位置与版本

| 版本 | 文件 | 说明 |
|------|------|------|
| 发布_鸟类应用_20261015_002 | 打包源码\model_trainer.py | 可读版，日志函数为 `log()` |
| 发布_鸟类应用_20261016_001 | 程序\model_trainer.py | 混淆版，日志函数为 `_v7552da09()` |

两处修改内容一致，仅日志函数命名按各自版本风格。

## 四、验证

1. **语法验证**：两个版本的 `model_trainer.py` 均通过 `python -m py_compile`。
2. **防护验证**：构造「只有 train、无 val」的 3 类临时数据集运行，输出 `val: 0 张` 后立即报错退出（退出码 1），不再静默训练出全 0 指标。
3. **自动划分验证**：构造「每类 4 张」的临时数据集加 `--auto-split`，正确切出 `val: 3 张`，指标非零（top1=0.6667、top5=1.0、macro_f1=0.5556），验证自动划分是有效的解决路径。
4. **边界确认**：每类图片 < 3 张时，`per_class_adaptive_split` 按小类保底规则全部进训练集，val 仍为 0 并被防护正确拦截——这是数据过少的正常表现，非代码缺陷。

## 五、相关发现

排查过程中确认：目标版本 `20261015_002` 模型库 registry.json 中的 `resnet50_10月16日_001` 记录（3 类、所有指标 0.0、上午 10:57 训练）正是本次问题现象的产物，证明用户实际运行的是该版本。该记录为用户原有数据，已保留未删；本次测试产生的 `_临时验证输出2` 记录已从 registry 删除，相关临时目录已清理。
