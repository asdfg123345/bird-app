### 3. 核心验证点

- **适应模式**：完整走通数据扫描 → 显存预算推导（55%） → 内存约束 → 批大小实测探测 → 模型构建 → 训练 → 最佳模型保存 → 结束评估 → 注册入库。
- **低速模式**：批大小严格固定为 8（符合预设），一轮 2150 个批次。
- **高速模式**：批大小按 80% 显存预算推导为 145，经实测探测收敛到 108（实测探测机制生效）。
- **自定义模式**：显式指定的 SGD 优化器、学习率 0.01、批大小 64、混合精度全部生效；学习率余弦退火正确执行（0.01 → 0.0075 → 0.0025）。
- **GUI 真实调用路径**：不传输出目录时，脚本自动取号生成 `yanzheng_gui_10月16日_001` 目录，并成功生成预览图 preview.jpg（16.1KB）。
- **模型参数有效性**：四种模式的 best_model.pt 均可正常加载，参数量 23.97M（320 个张量），分类头 fc 形状为 (200, 2048)，与 200 类正确对应。
- **优化器状态差异**：AdamW 模式断点文件 280MB（含一阶/二阶动量），SGD 模式 187MB（仅动量缓冲），证明优化器状态被正确保存。

### 4. 产物完整性

每种模式的输出目录均含 9 个文件：best_model.pt（91.5MB）、last_model.pt、resume_state.pth、labels.json、meta.json、evaluation_report.json、per_class_metrics.csv、training_history.json、train_log.txt；GUI 路径额外含 preview.jpg。meta.json 完整记录训练参数与配置，evaluation_report.json 完整记录验证集与检测集指标。

### 5. 重要观察点

1. **低速模式收敛显著偏弱**：batch=8 在 200 类任务上两轮后 top1 仅 3%，远低于适应模式（47.85%）和高速模式（46.36%）。原因是大规模多类任务下小批量梯度过少、批归一化统计不稳定。建议后续将低速模式的批大小改为「按设备推导但更保守（如下限 32）」，而非固定 8，以兼顾低占用与收敛质量。
2. **学习率与优化器影响显著**：自定义模式采用 SGD + 学习率 0.01，三轮即达 62.23%，明显优于 AdamW + 学习率 0.001 的两轮结果，说明推荐参数中针对 ResNeSt 系给出的「SGD + 0.01」策略方向正确，可考虑推广为通用推荐。
3. **预览图生成条件**：仅在模式化训练且未显式指定输出目录时生成（GUI 正常使用路径）；显式指定输出目录时为保持旧产物结构不生成，此行为符合代码设计。
4. **系统可用内存偏低**：测试期间系统可用内存约 2.8~3.5GB，导致数据加载进程被内存约束压至 1，数据加载可能成为瓶颈，建议训练前释放内存。
